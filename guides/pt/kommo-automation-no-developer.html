Automações no Kommo sem programador (2026)

Equipe Kai · Atualizado em 24 de setembro de 2026

A maior parte da automação do dia a dia no Kommo dispensa programador: no Pipeline Digital você associa um gatilho a uma etapa (tarefa, tag, mudança de etapa, e-mail, webhook), e no Salesbot monta um fluxo com blocos prontos. Os três cenários mais comuns — uma tarefa ao mudar de etapa, um lembrete quando o cliente some e uma notificação no Telegram de lead ganho — levam 10–30 minutos cada com as ferramentas nativas. Se você prefere não aprender o construtor, descreva a regra em palavras simples e o Kai configura tudo pela API oficial do Kommo.

Resumo

  • O Pipeline Digital fica em Leads → Automate; cada etapa oferece 12 tipos de gatilho e 5 opções de atraso: Immediately, End of the day, In 1 day, In 3 days, End of the week.
  • Salesbot: construtor de fluxos, sem limite de passos, timer de Pause de até 8.760 horas; dispara com uma nova mensagem, com a entrada do lead em uma etapa, com a troca de responsável ou por agendamento. Não está no plano Base.
  • Não existe a ação nativa “postar em um grupo do Telegram”: as opções são uma mensagem interna para um colega, um webhook ou um widget do Marketplace.
  • Um integrador normalmente leva 3–5 semanas. Kai: uma mensagem no chat, a partir de €29/mês, 3 dias grátis, sem cartão.

O que são o Pipeline Digital e o Salesbot

O Pipeline Digital (Digital Pipeline) é a automação ligada às etapas do funil. Embaixo de cada etapa do quadro você pendura uma regra: “quando um lead chegar aqui, faça X”. Uma regra pode esperar, checar uma condição (tag, responsável, valor de campo) e executar uma ação.

O Salesbot é um construtor de fluxos com vários passos. Ele faz tudo o que os gatilhos fazem e ainda conversa com o cliente nos chats: mensagens com botões, espera por resposta, ramificações, tarefas, webhooks. Ele é iniciado como gatilho do Pipeline Digital ou por eventos de chat. Os nomes de menu abaixo seguem a ajuda oficial do Kommo em inglês.

O que você mesmo pode configurar

Gatilhos do Pipeline Digital, segundo a ajuda oficial: Salesbot, Add task, Create lead, Send email, Send webhook, Change lead stage, Add tags, Complete tasks, Generate form, Change lead's user, Change field, Delete files. Cada gatilho aceita condições por usuário responsável, tags e campos; marque Apply the trigger to all leads already in this stage, senão a regra vale só para os leads novos.

Os blocos do Salesbot se dividem em passos de conversa (Message, Condition, Pause, Validation, Send internal message) e ações (Add task, Change lead status, Manage tags, Set field, Change responsible user, Send email, Send webhook, Widget, Round Robin). Os modelos prontos facilitam o começo.

Cenário 1. Uma tarefa para o vendedor quando a etapa muda

Na mão, no Kommo

  1. Abra Leads → Automate.
  2. Embaixo da etapa desejada, clique em “+” → Add trigger → Add task.
  3. Preencha o texto da tarefa, o tipo, o usuário responsável e o prazo (Immediately, End of the day, In 1 day, In 3 days, End of the week).
  4. Adicione uma condição, se precisar (por exemplo, só leads com a tag “Quente”), e salve. Teste primeiro em um lead.

O mesmo no amoCRM: Leads (Сделки) → Setup (Настроить) → “Add trigger” embaixo da etapa → “Create task”.

Com o Kai

Mensagem no bot do Telegram ou no chat webQuando um lead passar para a etapa “Proposta enviada”, crie uma tarefa para o responsável: “Confirmar que o cliente recebeu a proposta”, com prazo até o fim do dia. Só para leads com a tag “Quente”.

O Kai pergunta se a etapa tem outro nome, mostra o plano e cria o gatilho pela API; o relatório fica no histórico do chat.

Cenário 2. Um lembrete quando o cliente some

Na mão, no Kommo

O Kommo não tem um gatilho específico de “cliente não respondeu”, então há dois caminhos.

  1. Simples, sem Salesbot. Na etapa “Proposta enviada”, adicione um gatilho Add task com prazo In 1 day: “Sem resposta — ligar para o cliente”. Se o cliente responder antes, o vendedor fecha a tarefa.
  2. Preciso, com Salesbot. Settings → Communication tools → Salesbots → Create a new bot. Sequência: Message (texto de follow-up) → Pause esperando uma mensagem do cliente, com timer (por exemplo, 24 horas) → Add task para o vendedor. Depois adicione um gatilho Salesbot na etapa do Pipeline Digital e teste as ramificações em um chat de teste.

Mensagem para o KaiSe um lead ficar em “Proposta enviada” por mais de um dia sem atividade, crie uma tarefa para o responsável “Cliente sumiu, ligar de novo” e me avise no Telegram.

Cenário 3. Uma notificação no Telegram quando um lead é ganho

Na mão, no Kommo

  1. Dentro do Kommo. Um Salesbot disparado quando o lead entra em Closed – won, com um passo Send internal message. Só o usuário ou a equipe selecionados veem a mensagem, dentro do Kommo, e não em um chat externo do Telegram.
  2. Via webhook. Add trigger → Send webhook na etapa de ganho; o seu próprio bot do Telegram ou um conector (Albato, ApiX-Drive, Make, n8n, Zapier) formata a mensagem para o grupo.
  3. Via widget. O Kommo Marketplace tem widgets de terceiros para notificações no Telegram; o preço é definido por cada desenvolvedor.

Com o Kai

Mensagem para o KaiConfigure notificações: quando um lead for ganho, publique no grupo do Telegram da equipe de vendas o nome do lead, o valor e o responsável.

O Kai conecta integrações de leads com Telegram, Slack, Google Sheets e webhooks sem conector intermediário e não armazena os dados dos leads.

Limites que você só descobre depois

  • O Salesbot não está no plano Base (segundo a página de preços do Kommo no momento em que este texto foi escrito); o Pipeline Digital está em todos os planos.
  • Os atrasos dos gatilhos vêm de um conjunto fixo; “em 2 horas” exige uma pausa do Salesbot.
  • Os gatilhos reagem a eventos de etapa, não ao comportamento do cliente. As condições cobrem só usuário responsável, tags e campos.
  • Sem a caixa “aplicar aos leads que já estão nesta etapa”, a regra ignora os leads atuais — o motivo mais comum do “não acontece nada”.
  • Depois de 5–7 gatilhos, ninguém lembra o que está pendurado onde. A auditoria do funil do Kai existe justamente para achar essas sobreposições.

FAQ

Preciso de um programador para configurar o Pipeline Digital no Kommo?

Não. Os gatilhos do Pipeline Digital e os fluxos do Salesbot são montados com cliques na interface do Kommo. Um programador só é necessário para widgets sob medida ou webhooks complexos para sistemas externos.

Qual é a diferença entre o Salesbot e os gatilhos do Pipeline Digital?

Um gatilho é uma única ação disparada por um evento de etapa: tarefa, tag, e-mail, webhook. O Salesbot é um fluxo de vários passos, com mensagens ao cliente, pausas, condições e as mesmas ações dentro dele. O Salesbot não está incluído no plano Base.

O Kommo tem um gatilho de “cliente não respondeu”?

Não como gatilho separado. O silêncio é tratado com um passo Pause no Salesbot (esperar uma mensagem, com timer de até 8.760 horas) ou com uma tarefa do Pipeline Digital com atraso: In 1 day, In 3 days, End of the week.

Como enviar uma notificação no Telegram quando um lead é ganho?

Nativamente: Send internal message (só para usuários do Kommo), Send webhook para o seu próprio bot ou para um conector, ou um widget do Kommo Marketplace. O Kai conecta um canal de leads para o Telegram a partir de uma descrição no chat.

O mesmo funciona no amoCRM?

Sim, o Kommo é a versão internacional do amoCRM. No amoCRM o caminho é Leads (Сделки) → Setup (Настроить) → “Add trigger” embaixo da etapa → “Create task”. O Kai trabalha com os dois CRMs, além do Bitrix24 e de CRMs próprios com documentação de API.

O Kai substitui um integrador?

Para regras padrão como tarefas, tags, mudanças de etapa, notificações e integrações com Telegram, Slack ou Google Sheets, sim. Para lógica complexa com widgets sob medida e muitos sistemas externos, um integrador ainda é a escolha certa; o Kai pelo menos prepara o briefing em PDF.
