Como conectar um agente de IA a um CRM próprio (interno) pela API — sem reescrever o sistema

Atualizado em 1 de novembro de 2026 · Equipe Kai · 8 min de leitura

Muitas empresas usam um CRM próprio: escrito para o seu processo, hospedado no próprio servidor, e nenhum “assistente de IA para amoCRM” de prateleira serve. Você não precisa reescrever o sistema por causa disso. Se o CRM tem uma API REST que responde em JSON, um agente de IA se conecta a ele do mesmo jeito que a um CRM de mercado: você descreve onde a API fica, como autorizar e qual requisição faz o quê, e depois configura funis, cria tarefas e automações em palavras simples, no chat. Este guia cobre o que você precisa, como funciona no Kai e onde estão os limites.

Em resumo / TL;DR

  • São necessárias três coisas: um endereço de API em https em um host público, um método de autenticação (OAuth 2.0, chave de API, bearer ou basic) e um endpoint com a lista de funis. Todo o resto é opcional.
  • A conexão é feita com uma especificação do conector: um JSON que o Kai rascunha a partir da sua documentação ou monta passo a passo no chat. Nenhum código para escrever.
  • Depois disso, o agente trabalha com o seu CRM como com o amoCRM: funis e etapas, leads, contatos, empresas, tarefas, notas, campos, análises; os eventos do seu CRM alimentam regras “evento → ação”.
  • Teste primeiro no Kai Sandbox CRM — um CRM de teste do lado do Kai que se conecta exatamente como um real.
  • Segurança: só https, requisições só para o host da sua API, segredos criptografados, modelos sem código, limites de tamanho e de frequência.
  • Conectar o seu CRM próprio está no plano Max (€119/mês). Discutir o sistema e rascunhar a especificação é grátis.

O que “CRM próprio” significa para um agente de IA

“Próprio” aqui é qualquer CRM que não está na lista de integrações prontas: um sistema interno em Laravel ou Django, uma personalização em cima de um CRM open source como EspoCRM ou SuiteCRM, um portal interno com módulo de vendas, ou um CRM como HubSpot ou Pipedrive. Para o agente, não importa em que linguagem ele foi escrito. Ele precisa de três coisas: para onde enviar as requisições, como provar que é você e qual requisição faz o quê. No Kai, tudo isso é uma especificação do conector — um JSON de algumas dezenas de linhas. Especificações prontas para HubSpot, Pipedrive e EspoCRM já estão na documentação: cole, coloque o seu token, envie.

O que você precisa antes de conectar

  • A URL base da API — só https e só host público. O Kai rejeita endereços locais, redes privadas e endereços de metadados de nuvem, para que ninguém alcance a infraestrutura de outra pessoa através do agente.
  • Autorização de uma destas formas: OAuth 2.0 (authorization code com PKCE ou client credentials), token bearer, chave de API em um cabeçalho ou basic auth. Isso cobre o que a maioria das APIs internas consegue fazer.
  • Um endpoint de funis com etapas — a única operação obrigatória. Leads, contatos, tarefas, notas, campos, usuários são opcionais: descreva-os e o agente poderá usá-los; deixe-os de fora e ele dirá com franqueza que a operação não está disponível neste CRM e o que você precisa adicionar.
  • Respostas em JSON. O conector não aceita XML nem HTML.
  • Alguém que conheça o sistema. O Kai rascunha a especificação a partir de uma descrição, mas os nomes dos campos devem ser conferidos por alguém que já viu o código ou a documentação.

Três formas de conectar

  1. Sandbox. No chat do Kai — Telegram ou navegador — toque em “🔗 Conectar CRM” → “🔧 Meu CRM próprio via API” → “🧪 Testar o Kai Sandbox CRM”. O Kai sobe um pequeno CRM de teste do lado dele, com funis, leads, tarefas e eventos assinados, e o conecta exatamente como um CRM próprio real. Tudo o que está abaixo funciona lá também — o jeito mais rápido de ver o que o agente vai fazer com o seu sistema antes de escrever uma linha da especificação.
  2. A partir da documentação. Cole no chat alguns parágrafos descrevendo a sua API ou anexe um arquivo — o Kai rascunha a especificação, você confere os nomes dos campos e devolve.
  3. Passo a passo. O botão “🧩 Montar a especificação passo a passo”: o Kai pede o endereço da API, o método de autenticação e dois caminhos — funis e leads —, chama-os ele mesmo e lê os nomes dos campos nas respostas reais. Nenhum JSON para escrever; com OAuth 2.0 os campos são lidos logo depois que você autoriza.

Um JSON pronto pode ser enviado como texto ou como arquivo .json. Antes de salvar, o Kai valida a especificação — https, host público, placeholders, segredos — e diz exatamente o que corrigir. Para OAuth 2.0, aparece então um botão “Autorizar” para o lado do seu CRM; para os outros métodos, o Kai chama a lista de funis na hora e mostra o que vê. Alterne entre vários CRMs com /accounts.

Uma especificação mínima é um nome, a URL base, o bloco de autenticação e uma operação pipelines.list com os caminhos para os campos da resposta. Isso basta para conectar e ver os seus funis; o resto pode ser adicionado depois. O modelo e os exemplos estão na documentação do Kai.

Placeholders como {{name}} nos caminhos e nos corpos das requisições são preenchidos com os parâmetros da ação, {{secret.token}} com os segredos deste conector. Os caminhos de resposta usam pontos: data.items, result.0.id. O agente monta as requisições só com o que você descreveu: nenhum código, nenhum acesso a mais nada.

Segurança: o que o agente não consegue fazer com o seu sistema

  • Só https e só hosts públicos: os endereços são verificados tanto ao salvar a especificação quanto antes de cada requisição — o DNS é resolvido de novo.
  • As requisições vão só para o host da URL base: os caminhos na especificação são relativos, URLs absolutas e redirecionamentos são proibidos.
  • Modelos não são código: só placeholders. Eles não têm acesso ao ambiente do Kai, ao banco de dados nem a outros usuários.
  • Os segredos são armazenados criptografados, nunca vão para os logs e são ocultados nas mensagens de erro.
  • Limites: especificação de até 64 KB, corpo da requisição de até 256 KB, resposta de até 1 MB, timeout de 15 segundos, 60 chamadas por minuto por conector.
  • OAuth 2.0: um state assinado válido por 15 minutos, PKCE, um redirect URI fixo; o código é trocado pelo token só no servidor do Kai.

Você pode revogar o acesso a qualquer momento — exclua o token ou a chave do lado do seu CRM, e a próxima requisição do agente simplesmente não passa.

Limites: o que você não vai ter

  • Widgets ou botões dentro do seu CRM: o agente vive no chat e trabalha pela API; ele não adiciona nada à interface do sistema.
  • Operações que não estão na especificação: o Kai não adivinha endpoints, ele pede que você os descreva.
  • APIs sem JSON, com assinatura de requisição fora do padrão ou acessíveis só dentro de uma rede privada — primeiro é preciso um desenvolvedor.

Quando você precisa de um desenvolvedor

  • O CRM não tem API — ela precisa ser escrita. O mínimo: listas de funis e de leads; o resto, passo a passo.
  • Existe uma API, mas só dentro da rede local — você precisa de um endpoint https público com autorização.
  • Você quer eventos do CRM para automações — o CRM precisa enviar um webhook para o endereço do Kai: um POST com JSON.

Em todos os outros casos não é preciso desenvolvedor: o Kai rascunha a especificação, quem conhece o sistema confere.

Com o Kai é uma mensagem

Depois de conectado, falar sobre o seu CRM não é diferente de falar sobre o amoCRM: você descreve o que precisa, o Kai faz perguntas, mostra um plano, executa e envia um relatório. Exemplos:

FAQ

Meu CRM é interno, tem API, mas não tem documentação. Vai funcionar?

Sim. Envie exemplos de requisições e respostas ou um trecho do código do controller — o Kai rascunha a especificação. Ou monte passo a passo: informe o endereço, o método de autenticação e os caminhos para funis e leads; o Kai os chama e lê sozinho os nomes dos campos nas respostas.

É seguro dar a um agente de IA acesso ao meu CRM próprio?

O acesso se limita ao que a especificação descreve: requisições só para o seu host e só por https, modelos sem código, segredos criptografados, limites de tamanho e de frequência. Para revogar o acesso, exclua o token ou a chave do seu lado.

Quanto custa conectar o meu CRM próprio?

É o plano Max — €119/mês, até 10 contas de CRM, suporte prioritário. A discussão e o rascunho da especificação são grátis. Construir o CRM em si ou a sua API não faz parte do plano.

HubSpot, Pipedrive ou EspoCRM contam?

Sim. Para o agente, eles são os mesmos “CRMs próprios” via API: as especificações prontas para eles estão na documentação do Kai, você só precisa de um token ou de uma chave de API.
