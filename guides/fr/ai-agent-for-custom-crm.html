Comment connecter un agent IA à un CRM sur mesure (maison) via son API — sans réécrire le système

Mis à jour le 1er novembre 2026 · Équipe Kai · 8 min de lecture

Beaucoup d’entreprises utilisent leur propre CRM : écrit pour leur processus, hébergé sur leur propre serveur, et aucun « assistant IA pour amoCRM » du commerce ne lui convient. Inutile pour autant de réécrire le système. Si le CRM dispose d’une API REST qui répond en JSON, un agent IA s’y connecte comme à un CRM du marché : vous décrivez où se trouve l’API, comment s’authentifier et quelle requête fait quoi, puis vous configurez les pipelines, créez des tâches et des automatisations en langage courant, dans un chat. Ce guide explique ce qu’il faut, comment cela fonctionne dans Kai et où se situent les limites.

En bref / TL;DR

  • Il faut trois choses : une adresse d’API en https sur un hôte public, une méthode d’authentification (OAuth 2.0, clé API, bearer ou basic) et un endpoint qui liste les pipelines. Tout le reste est facultatif.
  • La connexion se fait par une spécification de connecteur : un JSON que Kai rédige à partir de votre documentation ou construit étape par étape dans le chat. Aucun code à écrire.
  • Ensuite, l’agent travaille avec votre CRM comme avec amoCRM : pipelines et étapes, transactions, contacts, entreprises, tâches, notes, champs, analytique ; les événements de votre CRM alimentent des règles « événement → action ».
  • Essayez d’abord sur Kai Sandbox CRM — un CRM de test côté Kai, qui se connecte exactement comme un vrai.
  • Sécurité : https uniquement, requêtes uniquement vers l’hôte de votre API, secrets chiffrés, modèles sans code, limites de taille et de débit.
  • La connexion de votre propre CRM est incluse dans le forfait Max (€119/mois). Discuter du système et rédiger la spécification est gratuit.

Ce que « votre propre CRM » signifie pour un agent IA

« Votre propre CRM », c’est ici tout CRM absent de la liste des intégrations prêtes à l’emploi : un système maison sous Laravel ou Django, une version adaptée d’un CRM open source comme EspoCRM ou SuiteCRM, un portail interne doté d’un module commercial, ou encore un CRM comme HubSpot ou Pipedrive. Le langage dans lequel il est écrit importe peu à l’agent. Il lui faut trois choses : où envoyer les requêtes, comment prouver que c’est bien vous et quelle requête fait quoi. Dans Kai, tout cela tient dans une spécification de connecteur — un JSON de quelques dizaines de lignes. Des spécifications prêtes à l’emploi pour HubSpot, Pipedrive et EspoCRM figurent déjà dans la documentation : collez-la, ajoutez votre token, envoyez.

Ce qu’il faut avant de se connecter

  • L’URL de base de l’API — uniquement en https et uniquement sur un hôte public. Kai refuse les adresses locales, les réseaux privés et les adresses de métadonnées cloud, pour que personne ne puisse atteindre l’infrastructure d’autrui à travers l’agent.
  • L’authentification, selon l’une de ces méthodes : OAuth 2.0 (authorization code avec PKCE ou client credentials), un bearer token, une clé API dans un en-tête ou basic auth. Cela couvre ce que savent faire la plupart des API maison.
  • Un endpoint des pipelines avec leurs étapes — la seule opération obligatoire. Transactions, contacts, tâches, notes, champs, utilisateurs sont facultatifs : décrivez-les et l’agent pourra s’en servir ; omettez-les et il vous dira honnêtement que l’opération n’est pas disponible pour ce CRM, et ce qu’il faut ajouter.
  • Des réponses en JSON. Le connecteur n’accepte ni XML ni HTML.
  • Quelqu’un qui connaît le système. Kai rédige la spécification à partir d’une description, mais les noms des champs doivent être vérifiés par une personne qui a vu le code ou la documentation.

Trois façons de se connecter

  1. Bac à sable. Dans le chat Kai — Telegram ou navigateur —, touchez « 🔗 Connect CRM » → « 🔧 My own CRM via API » → « 🧪 Try Kai Sandbox CRM ». Kai lance de son côté un petit CRM de test, avec pipelines, transactions, tâches et événements signés, et le connecte exactement comme un vrai CRM sur mesure. Tout ce qui suit y fonctionne aussi — le moyen le plus rapide de voir ce que l’agent fera de votre système avant d’écrire la moindre ligne de spécification.
  2. À partir de la documentation. Collez dans le chat quelques paragraphes qui décrivent votre API ou joignez un fichier — Kai rédige la spécification, vous vérifiez les noms des champs et la renvoyez.
  3. Étape par étape. Le bouton « 🧩 Build the spec step by step » : Kai demande l’adresse de l’API, la méthode d’authentification et deux chemins — pipelines et transactions —, les appelle lui-même et lit les noms des champs dans les réponses réelles. Aucun JSON à écrire ; avec OAuth 2.0, les champs sont lus juste après votre autorisation.

Un JSON prêt peut être envoyé en texte ou sous forme de fichier .json. Avant l’enregistrement, Kai valide la spécification — https, hôte public, variables, secrets — et vous indique précisément ce qu’il faut corriger. Pour OAuth 2.0, un bouton « Authorize » apparaît ensuite pour l’autorisation côté CRM ; pour les autres méthodes, Kai appelle aussitôt la liste des pipelines et montre ce qu’il voit. Passez d’un CRM à l’autre avec /accounts.

Une spécification minimale, c’est un nom, l’URL de base, le bloc d’authentification et une opération pipelines.list avec les chemins vers les champs de la réponse. Cela suffit pour se connecter et voir vos pipelines ; le reste peut être ajouté plus tard. Le modèle et des exemples se trouvent dans la documentation Kai.

Les variables comme {{name}} dans les chemins et les corps de requête sont remplies à partir des paramètres de l’action, {{secret.token}} à partir des secrets de ce connecteur. Les chemins de réponse s’écrivent avec des points : data.items, result.0.id. L’agent construit les requêtes uniquement à partir de ce que vous avez décrit : pas de code, aucun accès à quoi que ce soit d’autre.

Sécurité : ce que l’agent ne peut pas faire à votre système

  • https uniquement et hôtes publics uniquement : les adresses sont vérifiées à l’enregistrement de la spécification et avant chaque requête — le DNS est résolu à nouveau.
  • Les requêtes ne partent que vers l’hôte de l’URL de base : les chemins de la spécification sont relatifs, les URL absolues et les redirections sont interdites.
  • Les modèles ne sont pas du code : uniquement des variables. Ils n’ont aucun accès à l’environnement de Kai, à sa base de données ni aux autres utilisateurs.
  • Les secrets sont stockés chiffrés, ne sont jamais journalisés et sont masqués dans les messages d’erreur.
  • Limites : spécification jusqu’à 64 Ko, corps de requête jusqu’à 256 Ko, réponse jusqu’à 1 Mo, délai d’attente de 15 secondes, 60 appels par minute et par connecteur.
  • OAuth 2.0 : un state signé valable 15 minutes, PKCE, une URI de redirection fixe ; le code n’est échangé contre un token que sur le serveur de Kai.

Vous pouvez révoquer l’accès à tout moment — supprimez le token ou la clé côté CRM, et la requête suivante de l’agent ne passera tout simplement pas.

Limites : ce que vous n’aurez pas

  • Des widgets ou des boutons dans votre CRM : l’agent vit dans le chat et travaille via l’API ; il n’ajoute rien à l’interface du système.
  • Les opérations absentes de la spécification : Kai ne devine pas les endpoints, il vous demande de les décrire.
  • Les API sans JSON, avec une signature de requête non standard ou accessibles uniquement dans un réseau privé — il faut d’abord un développeur.

Quand il faut un développeur

  • Le CRM n’a pas d’API — il faut l’écrire. Le minimum : les listes des pipelines et des transactions ; le reste au fur et à mesure.
  • Il y a une API, mais uniquement dans le réseau local — il vous faut un endpoint https public avec authentification.
  • Vous voulez des événements du CRM pour les automatisations — le CRM doit envoyer un webhook à l’adresse de Kai : un POST en JSON.

Dans tous les autres cas, pas besoin de développeur : Kai rédige la spécification, la personne qui connaît le système la vérifie.

Avec Kai, un seul message suffit

Une fois la connexion établie, parler de votre CRM ne diffère en rien de parler d’amoCRM : vous décrivez ce dont vous avez besoin, Kai pose des questions complémentaires, montre un plan, exécute et envoie un rapport. Exemples :

Montre les pipelines de mon CRM et combien de transactions se trouvent à chaque étape.
Crée la transaction « Petit, cuisine » à 3 500 dans le pipeline « Ventes », contact Petit, téléphone +1 555 000-0000, et une tâche « rappeler » pour demain.
Quand une transaction passe à l’étape « Contrat », crée la tâche « émettre la facture » pour le responsable et écris-moi dans le chat.

La connexion de votre propre CRM est incluse dans le forfait Max : €119/mois, jusqu’à 10 comptes CRM, support prioritaire. Discuter du système, demander une ébauche de spécification et poser des questions est gratuit — pendant l’essai et sur tous les forfaits. Kai parle anglais et russe.

FAQ

Mon CRM est développé en interne, il a une API mais pas de documentation. Est-ce que ça fonctionnera ?

Oui. Envoyez des exemples de requêtes et de réponses ou un extrait du code du contrôleur — Kai rédige la spécification. Ou construisez-la étape par étape : donnez l’adresse, la méthode d’authentification et les chemins vers les pipelines et les transactions ; Kai les appelle et lit lui-même les noms des champs dans les réponses.

Est-il sûr de donner à un agent IA l’accès à mon propre CRM ?

L’accès est limité à ce que décrit la spécification : requêtes uniquement vers votre hôte et uniquement en https, modèles sans code, secrets chiffrés, limites de taille et de débit. Pour révoquer l’accès, supprimez le token ou la clé de votre côté.

Combien coûte la connexion de mon propre CRM ?

C’est le forfait Max — €119/mois, jusqu’à 10 comptes CRM, support prioritaire. La discussion et l’ébauche de spécification sont gratuites. Le développement du CRM lui-même ou de son API n’est pas inclus dans le forfait.

HubSpot, Pipedrive ou EspoCRM sont-ils concernés ?

Oui. Pour l’agent, ce sont des « CRM propres » via API comme les autres : des spécifications prêtes à l’emploi se trouvent dans la documentation Kai, il vous suffit d’un token ou d’une clé API.

Et ensuite ?

Ouvrez le chat Kai, touchez « Connect CRM » → « My own CRM via API » et commencez par le bac à sable ou envoyez votre documentation. Si le système a une API REST, il devient en une soirée un CRM que vous pilotez avec des mots.
